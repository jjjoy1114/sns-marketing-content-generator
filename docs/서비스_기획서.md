# 서비스 기획서 — 다알려드리미

> 작성: 오주연 · 최초 작성일 2026-08-15

## 1. 서비스 개요

- **서비스명:** 다알려드리미
- **한 줄 정의:** 사업 정보를 한 번만 입력하면, 네이버 블로그·인스타그램·네이버 플레이스 소식에 맞는 마케팅 글을 자동으로 만들어 주는 AI 웹 서비스.
- **서비스 목적:** 소상공인과 SNS 운영자가 플랫폼마다 따로 글을 쓰느라 드는 시간과 부담을 줄이고, 하나의 정보로 채널별 초안을 빠르게 확보하도록 돕는다.
- **제공 가치:** 반복 작성 시간 절약 · 플랫폼별 문체·길이 자동 대응 · 문의/방문으로 이어지는 행동 유도 문구(CTA) 자동 제안.

## 2. 타깃 사용자

- 소상공인과 1인 사업자
- SNS 운영을 직접 해야 하는 자영업자
- SNS 마케팅 대행자·콘텐츠 제작자
- SNS 마케팅 교육 수강생

### 해결하려는 문제

플랫폼마다 글의 길이와 문체가 달라 매번 따로 써야 하고, 무엇을 강조하고 어떻게 문의로 연결할지 정하기 어렵다. 지역·업종·타깃에 맞는 콘텐츠를 반복 작성하는 데 시간이 많이 들고, 초안 작성 경험이 부족한 사업자에게는 그 자체가 부담이다.

## 3. 페이지/섹션 구성

한 페이지 안에서 상단 메뉴로 각 섹션에 이동하는 방식으로 구현한다(과제 요구: 최소 3개 이상 섹션 + 메뉴 이동).

| # | 섹션 | 내용 | 메뉴 이동 |
|:---:|---|---|---|
| 1 | 메인·서비스 소개 | 서비스가 해결하는 문제와 핵심 기능 안내 (Hero) | `#home` |
| 2 | AI 글 생성기 | 입력 폼 · 생성 버튼 · 로딩 · 결과 카드 | `#generator` |
| 3 | 플랫폼별 작성 가이드·예시 | 블로그·인스타·플레이스 차이와 변환 예시 | `#guide` |
| 4 | FAQ·이용 안내 | AI 결과 검토, 과장 표현·개인정보 주의 | `#faq` |

상단 내비게이션에서 각 항목 클릭 시 해당 섹션으로 부드럽게 스크롤 이동한다.

## 4. 핵심 기능 — AI 마케팅 글 생성기

사용자가 사업 정보를 입력하고 플랫폼을 선택하면, AI가 해당 플랫폼 형식에 맞는 제목·본문·CTA·키워드를 생성해 결과 카드에 보여준다. 사용자는 결과를 확인하고 복사해 바로 활용한다.

**동작 흐름**

```text
사용자 정보 입력 → 입력값 검증 → fetch로 Python API 호출
→ AI가 선택 플랫폼 형식에 맞춰 콘텐츠 생성
→ 결과 카드에 제목·본문·CTA·키워드 표시 → 사용자 확인·복사
```

## 5. AI 기능 설계 — 입력 / 출력 / 실패 처리

과제 필수 항목. AI 기능의 입력·출력·실패 처리 기준을 명확히 정의한다.

### 입력 (사용자가 넣는 값)

| 항목 | 필수 | 설명 |
|---|:---:|---|
| 업종 | ✅ | 예: 카페, 미용실, 학원 |
| 지역 | ⬜ | 예: 김해시 내동 |
| 주요 고객 | ⬜ | 예: 20~30대 직장인 |
| 홍보할 상품/서비스 | ✅ | 예: 신메뉴 아메리카노 |
| 홍보 목적 | ✅ | 정보 제공 / 상품 홍보 / 후기 / 행사·모집 |
| 핵심 정보·강조점 | ⬜ | 예: 오픈 이벤트 2주간 |
| 핵심 키워드 | ⬜ | 예: 김해 카페, 아메리카노 |
| 작성 플랫폼 | ✅ | 네이버 블로그 / 인스타그램 / 네이버 플레이스 소식 |
| 원하는 말투 | ⬜ | 친근함 / 정중함 / 활기참 |

### 출력 (AI가 돌려주는 값)

- 플랫폼에 적합한 **제목**
- 게시물 **본문**
- **행동 유도 문구(CTA)**
- **해시태그 또는 검색 키워드**
- 이미지·썸네일용 **짧은 문구**

결과는 항상 일정한 구조(JSON)로 반환하여 화면 카드에 항목별로 표시한다.

### 실패 처리 기준 (과제 필수: 최소 1개 이상 → 3개 모두 구현)

| 상황 | 사용자에게 보여줄 안내 |
|---|---|
| 빈 입력(필수값 누락) | "필수값을 입력하세요" 안내 표시, **API 호출하지 않음** |
| API 오류(4xx/5xx) | 오류 원인은 노출하지 않고 "잠시 후 다시 시도하세요" 안내 |
| 지연/타임아웃 | "처리 중입니다" 표시 후, 지연 시 재시도 안내 |

추가로 지나치게 긴 입력에는 글자 수 제한 안내를 표시한다.

## 6. 플랫폼별 출력 원칙

| 플랫폼 | 출력 방향 |
|---|---|
| 네이버 블로그 | 검색 의도에 맞는 제목, 소제목과 문단, 지역·서비스 정보, 자연스러운 문의 유도 |
| 인스타그램 | 시선을 끄는 첫 문장, 짧고 읽기 쉬운 본문, 공감·반응 유도, 관련 해시태그 |
| 네이버 플레이스 소식 | 핵심 혜택과 이용 정보 중심의 간결한 안내, 방문·예약·문의 유도 |

## 7. 기술 스택

- **프론트엔드:** 순수 HTML · CSS · JavaScript (React/Vue 등 프레임워크 미사용)
- **백엔드:** Vercel Serverless Functions (Python, `api/` 폴더)
- **AI 연동:** OpenAI API (환경 변수에 저장한 API 키 사용)
- **호출 방식:** 프론트에서 `fetch('/api/generate')`로 Python API 호출
- **배포:** GitHub 저장소 + Vercel 연동

## 8. 보너스 과제 — 다크 모드

UX 고도화 영역에서 **다크 모드 하나**를 선택한다.

- 헤더에 라이트·다크 전환 버튼 배치
- CSS 변수로 배경·글자·카드·버튼 색상 전환
- 선택한 모드를 `localStorage`에 저장 → 새로고침·재방문 후에도 유지
- 모바일·데스크톱 모두에서 정상 작동

## 9. 과제 범위에서 제외 (초기 버전)

SNS 계정 로그인·자동 게시, 이미지 업로드·분석, 콘텐츠 DB 저장, 실제 예약·결제, 모든 SNS 플랫폼 지원, 검색 순위·AI 인용 자동 측정 등은 초기 범위에서 제외한다.
